Network Guide

Understand your connection

Plain-language help for the measurements and network details shown by PingMetric.

speed Mbps vs MB/s

b means bit; B means byte. Eight bits equal one byte. ISPs normally advertise Mbps, while download tools often use MB/s. They describe the same throughput in different units.

MB/s = Mbps / 8 · Mbps = MB/s × 8

8 Mbps ≈ 1 MB/s; 40 ≈ 5; 80 ≈ 10; 100 ≈ 12.5; 1,000 ≈ 125. Real downloads can be lower because of Wi-Fi, overhead, congestion, server limits, devices, and other traffic.

download Download and upload

Download is data arriving at your device: websites, streaming and app or cloud downloads. Upload is data leaving it: video calls, backups, file uploads and live streaming.

Latency, ping, jitter and RTT

Latency is response time in milliseconds; lower is generally better for browsing, gaming, calls, remote desktops and cloud apps. PingMetric measures browser HTTP/application latency and TCP information where available—not raw ICMP ping, because browser JavaScript cannot send arbitrary ICMP Echo requests.

People often say “ping” for response time; classic ping normally uses ICMP. RTT is device → server → device time. MinRTT is the lowest observed RTT and RTTVar is its variation.

Jitter

Jitter is latency variation. 20, 21, 19, 20 ms is stable; 20, 80, 25, 110 ms is not. PingMetric uses the average absolute difference between consecutive HTTP/application samples. It matters for VoIP, video, games, streaming and remote control.

Loaded latency

Idle latency is responsiveness without traffic. A large rise during load can indicate queueing often associated with bufferbloat, but one browser test cannot diagnose it definitively.

TCP and retransmission

TCP reliably delivers ordered data using acknowledgements, retransmissions and congestion control. PingMetric’s TCP retransmission estimate is (bytesRetrans / bytesSent) × 100 when those fields exist. It is not exact packet loss; a higher value can reflect congestion, Wi-Fi interference, unstable paths or temporary loss.

IP, routing and dual stack

IPv4 uses 32-bit addresses such as 192.0.2.10; IPv6 uses 128-bit addresses such as 2001:db8::1234. A connection can be IPv4 only, IPv6 only, dual stack (both protocols, not two connections), or unknown.

A public IP can reveal network ownership and approximate region, not usually a precise home address. VPNs, proxies, mobile and CGNAT complicate interpretation.

ASN means Autonomous System Number (for example AS55836), identifying a routing organization. CIDR such as 203.0.113.0/24 describes an IP range. RIR means Regional Internet Registry, an organization that allocates number resources.

WebRTC and privacy

WebRTC supports browser calls, peer-to-peer data and real-time media. ICE candidates may include host, server-reflexive (srflx), or relay addresses; STUN, TURN and mDNS protections influence what is exposed. An additional public address is not automatically a VPN leak.

Network intelligence and browser APIs

VPN, proxy, Tor, datacenter, mobile, satellite, anycast, bogon/reserved, crawler/bot and known-abusive classifications come from external IP intelligence and can have false positives or negatives. Network Information API values (effective type, downlink, RTT) are browser estimates, not M-Lab results. Web Crypto availability does not mean the whole connection is secure.

PingMetric uses M-Lab NDT7 for active end-to-end upload/download measurement with a measurement server and test data. Results do not guarantee an ISP-plan speed. DNS leak testing needs controlled DNS infrastructure, so it is unavailable in browser-only mode.

What should I avoid sharing?

Be cautious with screenshots containing full IPv4/IPv6, WebRTC addresses, coordinates, postal code, city plus network identity, ISP/ASN plus exact IP, or CIDR/route. Together, public routing details can make profiling easier. Speeds, latency, jitter, dual-stack status and generic browser support are generally less sensitive. Use “Hide sensitive info” before sharing; it visually hides details but is not encryption.
